# 写真の貼り付け・既存付箋の送信と投稿

## 写真を貼る

1. 付箋の作成・編集画面で、本文の挿入したい場所をクリックします。
2. 「写真を貼る」を押してJPEGまたはPNGファイルを選びます。
3. 本文に写真が表示されたら「保存する」を押します。

写真ファイルのドラッグ＆ドロップにも対応します。画像データを取得できるブラウザでは、画像をコピーして本文へ貼り付けることもできます。IE11などで画像の貼り付けができない場合は「写真を貼る」を使用してください。複数ファイルを渡した場合は先頭の1枚を取り込みます。

写真は1件につき3枚まで、元ファイルは1枚10MB以下です。ブラウザ内で長辺1024ピクセル以下・埋め込みデータ200000文字以下へ縮小し、JPEGとして保存します。PNGの透明部分は白になります。元のファイルは変更せず、ファイル名・撮影位置などのメタデータは保存しません。元画像の画質を保持する原本保管機能ではありません。

写真をクリックして「写真削除」を押すと本文から除けます。「保存する」までは元の付箋を変更しません。写真の処理中は保存できず、編集中の画面を閉じた場合は遅れて届いた写真を別の付箋へ挿入しません。

## 既存の付箋を別のユーザーへ送る

1. 付箋上部の「編集」と同じ行にある「→」、または付箋を開いて「別のユーザーへ送る」を押します。矢印にマウスを重ねると操作名を表示します。
2. 送信先に `@利用者ID`、`#部署名` などを指定します。複数宛先はカンマで区切れます。
3. 内容を確認し「送信する」を押します。

元の付箋は残し、本文・表・写真・タイトル・期限・色を持つ新しい送信付箋を作成します。履歴・ゴミ箱状態・固定状態などは共有しません。編集画面から送る場合は、画面上の編集中の内容を送信し、元の付箋へは保存しません。

受信付箋からの転送もできます。元の送信者・元付箋ID・転送者を暗号化データ内に保持します。受信者には読み取り専用で届き、変更する場合は自分の付箋へコピーします。

## 既存の付箋を「みんなの投稿」へ投稿する

1. 付箋上部の「↑」、または付箋の編集・閲覧画面の「投稿する」を押します。矢印にマウスを重ねると「みんなの投稿へ投稿する」と表示します。
2. タイトル・本文・写真・表と分類を確認します。
3. 「投稿する」を押し、公開範囲の確認に同意すると投稿します。確認をキャンセルした場合は投稿しません。

公開範囲は **投稿時点で有効な登録利用者全員** です。後から新規登録した利用者への過去投稿の鍵配布は行いません。投稿前に写真や本文に公開してよい情報だけが含まれていることを確認してください。

元の付箋は残り、変更履歴は投稿しません。投稿一覧でも表・写真を表示し、投稿から自分の付箋へコピーしても保持します。通常のテキスト投稿も引き続き利用できます。

## SharePointの保存設定

**StickyNotesリストの設定 → 詳細設定 → 添付ファイルを有効** にしてください。リスト・列の追加や、管理者による写真ファイルの手動配置は不要です。設定画面のSharePoint診断でも添付ファイルの有効状態を確認します。

本文・写真・履歴は暗号化してから保存します。暗号化JSONが50000文字を超える場合は、既存のStickyNotesにアプリ内部用の保管行を作り、その添付へ暗号化JSONを保存します。通常の付箋・投稿行には短い参照情報だけを保存します。これは複数行テキスト列の[文字数上限](https://support.microsoft.com/en-us/sharepoint/lists/data-and-lists/list-and-library-column-types-and-options)を超えないためです。添付の読み書きには[SharePointのリスト添付REST API](https://learn.microsoft.com/en-us/sharepoint/dev/sp-add-ins/working-with-folders-and-files-with-rest#working-with-files-attached-to-list-items-by-using-rest)を使用します。

- 保管行は `Title=encrypted-storage`、`NoteType=BLOB`、`Deleted=はい` です。付箋・タスク・ゴミ箱には表示しません。
- **Deletedが「はい」でも、この保管行と添付ファイルは手動削除しないでください。** 保存済みの付箋・投稿・SharePointの履歴から参照されている可能性があります。
- 保管用添付を先にアップロードし、その後に本体を保存します。アップロード失敗では新しい付箋・投稿を公開しません。
- 更新競合や通信断で、使用されなかった保管行・添付が残る場合があります。保存結果が不明な場合に既存データを壊さないため、自動削除しません。参照を確認せずに一括削除しないでください。
- 添付は同じリストの読み取り権限で取得します。ユーザー別の復号は従来どおり暗号鍵で制御します。SharePointの既存の権限設定・認証が前提です。
- リストのバックアップには添付も含めます。リスト行だけの移行では大きな付箋・写真・投稿を復元できません。
- 1回の保存データは写真・履歴・暗号化情報を含め8MBまでです。超えた場合はエラーにし、履歴を無断で削除しません。「コピー」で新しい付箋にする方法があります。
- 端末内モードでは従来のブラウザ保存領域へ暗号化して保存します。写真が多いと保存容量の上限に達します。容量不足を成功とは表示しません。
- 現在は更新時に参照先の暗号化データを読み込みます。写真・利用者・投稿が多い環境では転送量と復号時間が増えるため、実環境の性能確認が必要です。

## 確認範囲

自動テストで写真の保持、宛先限定の表示、転送、履歴の非共有、投稿の確認・キャンセル、写真と表を保った投稿・コピー、添付の失敗・破損・更新競合・結果不明時の保護を確認します。画像縮小は模擬Canvas、SharePointは模擬応答による確認です。実際の写真デコード、IE11・Edge95実機の表示・クリップボード、SharePointの添付設定・権限は実環境での確認が必要です。
