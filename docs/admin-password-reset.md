# 管理者によるパスワード初期化

## 初回は管理者パスワードの登録だけ

1. ログイン画面の「管理者用：パスワード初期化」を開きます（`admin.html` → `index.html#admin`）。
2. 管理者パスワードを12文字以上で入力し、確認欄にも入力します。
3. 「登録する」を押し、「登録が完了しました」と表示されたら完了です。

**復旧鍵のファイル作成・ダウンロード・選択・配置は不要です。** コードや設定ファイルへパスワードを書く必要もありません。今回のコード変更では、実際の管理者パスワードは登録していません。

SharePoint連携時は、既存のリストと接続設定が正常で、現在のSharePointアカウントがサイトコレクション管理者であることが前提です。管理画面はHTTPSで配信してください。一般のサイトメンバー、アプリ内の名前・部署・設定フラグでは管理者になりません。

端末内モードでは、同じブラウザの保存領域に最初に登録したパスワードを使います。独立したサーバーの管理者認証はないため、初回設定は管理責任者が行ってください。

## 設定の保存先

| モード | 自動保存先 | 他の端末での利用 |
|---|---|---|
| SharePoint連携 | 既存の `StickyUsers` リストの管理者設定行 | 同じサイト・リストに接続する管理者は同じパスワードを使用 |
| 端末内 | 同じブラウザの `localStorage` 内の管理者設定行 | 共有されない。ブラウザデータ削除で設定も付箋も失われる |

アプリが復旧鍵を生成し、管理者パスワードで暗号化した状態だけを保存します。入力したパスワードと平文の秘密鍵は、リスト・端末保存・操作履歴へ保存しません。

- **リスト・列の追加は不要です。** 管理者設定行はアプリが作成します。手動で追加しないでください。
- 管理者設定行は `StickyUserId = __fsn:admin-recovery:v1`、`Title = fsn-admin-recovery-v1`、`Enabled = いいえ` です。通常のログイン、利用者一覧、送信先一覧には使用しません。
- 公開鍵を `PublicKey`、暗号化した復旧鍵のJSONを `EncryptedPrivateKey` に保存します。この2列はプレーンテキストの複数行テキストです。
- **管理者設定行を削除・編集・有効化しないでください。** 登録済みの設定は初回登録画面から上書きできません。
- 初期登録が同時に行われた場合は、最も小さいアイテムIDの設定を採用し、後から保存した側には登録失敗を表示します。後の候補行は使用しません。鍵が切り替わらないよう、先に登録した責任者のパスワードを使用してください。
- 読み込み失敗や設定破損を「未登録」とは扱いません。保存応答がタイムアウトした場合も、まず再読み込みして登録状態を確認してください。
- 一般利用者は公開鍵を読み取る必要があります。SharePoint側で管理者設定行は利用者に読み取りを許可し、編集・削除は管理者に制限してください。設定行を含むリストのバックアップ・バージョン管理も維持してください。

管理者パスワードを忘れた場合は、登録した復旧鍵を開けません。再登録で解決することはできないため、責任者がパスワードを保管・引き継いでください。復旧鍵を再生成する変更機能はありません。

## 利用者を復旧可能にする

新規利用者は、登録時に保存済みの管理者設定を読み取り、自動で復旧対応になります。

**既存利用者は管理者登録後に一度パスワードを入力して正常ログインしてください。** 同じ利用者鍵を使った復旧用情報が自動で追加されます。自動ログインだけでは追加されません。

復旧登録前に本人のパスワードと利用できる秘密鍵情報をすべて失った場合、後から管理者パスワードを登録しても過去の付箋を復号できません。未登録の利用者への初期化は止め、元データは変更しません。

旧ファイル方式を既に設定していた環境では、同じ復旧鍵を引き継ぐ移行が必要です。旧 `RECOVERY_PUBLIC_KEY` が設定された状態での新規登録は止めます。公開鍵だけから秘密鍵は復元できません。旧設定や鍵を削除せず、別途移行を依頼してください。新規導入では `js/recovery-config.js` は空の設定のまま使用します。

## パスワードを忘れたとき

1. 利用者は管理者へ連絡し、組織の手順で本人確認を受けます。
2. 管理者は管理画面の一覧から、名前・部署・IDを確認して対象を選択します。
3. 登録した管理者パスワードを入力して「仮パスワードを発行」を押し、確認画面で対象を再確認します。
4. 成功時に表示される仮パスワードを、本人へ安全な別経路で渡します。共有掲示板や監査ログへ貼らないでください。
5. 「パスワードの表示を消去」を押します。
6. 本人は24時間以内に仮パスワードでログインし、異なる10文字以上の新しいパスワードへ変更します。
7. 新しいパスワードで通常ログインします。自動ログインを使う場合は改めてチェックしてください。

仮パスワードは毎回ランダムに生成します。そのまま通常画面を開くことはできません。変更手続きを開いてから10分以内に完了してください。再発行すると、前の仮パスワードと進行中の変更手続きは無効になります。

通信タイムアウトでは書き込み結果が不明な場合があります。仮パスワードが表示されなかったからといって未更新とは決めつけず、状態確認後に必要なら再発行してください。

## データを保持する仕組み

利用者のRSA公開鍵・秘密鍵は作り直しません。同じ秘密鍵の保護パスワードだけを変更するため、復旧登録済みであれば暗号化済みの付箋・宛先鍵・SNSデータをそのまま使用できます。

パスワードのハッシュ、新しいパスワードで保護した同じ秘密鍵、セッション無効化情報を、1つの利用者行にまとめて更新します。ETagで更新競合を検出し、失敗を成功と表示しません。

初期化で古いセッションと自動ログインはアプリの次の確認時に拒否されます。既に表示・コピーされた情報や秘密鍵を遠隔消去する機能ではありません。対象ID・実行者・日時の操作履歴は管理者端末に保存しますが、改ざん防止された監査証跡ではありません。

## 簡略化による安全性の限界

暗号化した復旧鍵をアプリのデータと同じ場所に保存するため、そのデータを読める人は管理者パスワードの推測をオフラインで試せます。短い・使い回しのパスワードを避け、長く推測しにくい管理者パスワードを使用してください。管理者パスワードと保存済みの復旧情報を得た人は、復旧登録済み利用者の秘密鍵を取り出し、その暗号化データを復号できます。

SharePointの管理者判定には `currentuser.IsSiteAdmin` を使用します（[Microsoftの説明](https://learn.microsoft.com/en-us/previous-versions/office/sharepoint-visio/jj247052%28v%3Doffice.15%29)）。JavaScriptだけの判定はセキュリティ境界にはなりません。一般利用者が他人の利用者行や管理者設定行を更新できないことを、SharePoint側の権限で設定・確認してください。

静的HTML/JSでは、サーバー側で本人の行の「どの列をどの手順で変更したか」を完全には強制できません。改造クライアントに対しても厳密な初期化・期限・変更必須を強制する要件には、別途サーバー側の処理が必要です。関連する設計上の注意は [OWASPの鍵保管](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html#key-storage) と [パスワード復旧](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html) を参照してください。

## 確認範囲

自動テストで初回登録、再読み込み、ファイルなしの初期化、既存付箋の復号、旧ログイン拒否、変更必須、期限、権限不足、誤パスワード、保存失敗、設定破損、同時登録を確認します。IE11・Edge95実機、実際のSharePoint認証・リスト権限・別端末接続は実環境での確認が必要です。
