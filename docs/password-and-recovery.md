# 端末の自動ログインとパスワード忘れへの対応

## 今回実装した機能

ログイン画面の「この端末では次回からパスワード不要（30日間）」を選んで、通常どおり一度ログインします。次回は同じ端末・同じブラウザプロファイル・同じ配置先から開くと自動ログインします。初期状態はオフです。「ユーザーIDを記憶する」とは独立した設定です。

- 保存内容は端末用トークンと復号に必要な秘密鍵情報です。入力したパスワード自体は保存しません。
- 自動ログイン時も利用者の有効状態、トークン、端末ID、セッションの有効期限・失効状態、認証情報の変更を確認します。SharePointモードでは現在のSharePointアカウントとの一致も確認します。通信できない場合、保存情報だけでSharePointへログインすることはありません。
- 自動ログインは既存セッションを再開します。再読み込みのたびに新しいセッションを作ったり、有効期限を延長したりしません。
- 選択した場合の期限はログインから30日です。選択しない通常セッションは8時間です。
- 「ロック」「ログアウト」は端末の保存情報を削除してセッションを失効させ、次回はパスワード入力を求めます。
- 設定の「この端末の自動ログインを解除」は、現在の画面を開いたまま保存情報を削除し、トークンを更新します。以前コピーされたトークンも、アプリのセッション照合では使えなくなります。
- 保存に失敗した場合はログインを継続できますが、次回はパスワードが必要である旨を表示します。通信・保存解除の失敗はエラー一覧へ記録します。
- SharePointのリストや列の追加は不要です。既存のStickyUsers・StickySessionsの列を利用します。

## 安全性と限界

これは利便性のための保存であり、Windowsの資格情報管理やブラウザのパスワードマネージャーと同等の保護ではありません。保存した秘密鍵情報にはAES-GCMを使用しますが、その復号用の情報も同じブラウザにあります。**ブラウザデータを読める人やプログラム、同一オリジン上で動く不正なJavaScriptからは秘密を守れません。**パスワードを平文で保存しないことと、端末内情報の窃取に耐えることは別です。

共用端末では選択しないでください。端末を離れる際はアプリとWindowsをロックしてください。コピー済みの秘密鍵を遠隔で消去することはできません。期限・失効の確認はアプリへのログイン制御であり、盗まれた秘密鍵そのものの復号能力を失わせるものではありません。

本番環境で機密情報を扱う場合は、保存用認証情報をサーバー側で管理し、HttpOnly・Secure Cookieなどで保護する方式を別途設計してください。静的HTML/JSのみの現構成ではHttpOnly Cookieを発行できず、SharePointの権限設定を含むサーバー側の対策も必要です。OWASPもJavaScriptから読めるlocalStorageへ認証トークンを保存しないよう推奨しています：[HTML5 Security Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/HTML5_Security_Cheat_Sheet.html)。この制約を踏まえ、本機能は利用者が明示的に選ぶ設定にしています。

## パスワードを忘れた場合：管理者による初期化

管理者が本人確認後に仮パスワードを発行し、利用者が次回ログイン時に新しいパスワードへ変更する方式を実装しました。仮パスワードは24時間有効で、そのまま通常画面を使用することはできません。

利用者の既存の秘密鍵を保持したまま保護用パスワードを変更するため、復旧登録済みであれば過去の付箋も引き続き読めます。初期化で利用者の公開鍵・秘密鍵を作り直すことはありません。

導入時は管理画面で初回に管理者パスワードを登録するだけです。復旧鍵は暗号化して自動保存し、ファイル操作は不要です。既存利用者は設定後に一度正常ログインして復旧情報を登録します。未登録のままパスワードや秘密鍵を失った場合、過去の付箋は復号できません。

詳しい設定・操作・権限上の注意点は [管理者によるパスワード初期化](admin-password-reset.md) を参照してください。利用者自身が復旧用ファイルを発行してリセットする方式は採用していません。

## 確認範囲

自動テストは端末内データと模擬SharePoint応答を使用しています。IE11・Edge95実機、組織のSharePoint認証やブラウザ保存ポリシーは別途実環境で確認が必要です。
